# 서비스 정책

PRD를 기준으로 한 개발 초안. 별도 표시한 제안·미정 항목은 구현 전에 확정한다.

## 사용자와 인증

- 핵심 기능은 로그인 후 이용하며, 초기에는 구글 로그인만 제공한다.
- 인증 방식: 구글 소셜 로그인(OIDC) → 서버 세션 생성 → 세션 쿠키로 로그인 유지. 서비스용 JWT는 발급하지 않는다.
- 최초 구글 로그인 시 회원을 자동 생성한다. 사용자 식별은 `oauth_provider`와 `oauth_subject` 조합을 사용하며, 구글의 `sub`를 저장한다. 이메일은 식별키로 사용하지 않는다. [구글 공식 문서](https://developers.google.com/identity/openid-connect/openid-connect)
- 이메일은 필수 수집하며 구글의 확인 여부를 검증한다. 같은 소셜 계정으로 재로그인하면 검증된 이메일을 갱신하고, 기존 닉네임은 유지한다. 신규 닉네임은 구글 표시명에서 최대 50자로 정리한다.
- 동시 최초 로그인은 DB 유일 키와 PostgreSQL `ON CONFLICT`로 중복 생성을 방지한다. 다른 DB 오류를 중복 가입으로 숨기지 않는다.
- MVP 세션은 서버 메모리에 저장하고 비활성 만료 기본값은 30분이다. 서버 재시작·만료 시 재로그인한다. `user_sessions` 테이블·서비스 JWT·별도 비밀번호를 사용하지 않는다.
- 로그아웃 시 서버 세션을 무효화하고 세션 쿠키를 제거한다. 다른 사용자의 취향·독서 기록에는 접근할 수 없다.
- 상태 변경 요청은 세션 기반 CSRF 보호를 적용한다. 비로그인 허용 `GET /api/csrf`에서 토큰을 조회하고 로그인·로그아웃 후 다시 받는다. 로그아웃에는 인증과 유효한 토큰이 모두 필요하다.
- `local`·`prod` 프로필과 실제 DB·구글·프런트 환경변수는 각각의 실행 환경에서 설정한다. 로컬 쿠키의 `Secure` 기본값은 `false`, 운영은 `true`, `SameSite` 기본값은 `lax`다. 운영 도메인·브라우저 쿠키 동작은 배포 시 확인한다.

## 독서 분량과 진행

- 사용자는 PRD에 따라 1~10장 중 원하는 정수 분량을 자유롭게 선택한다. 1장의 기준은 미정이다.
- DB는 본문 구간과 `target_segments`로 분량을 관리한다. 장과 구간의 대응은 미정이며, 화면 크기에 따른 페이지 수를 저장 기준으로 사용하지 않는다.
- 도서·시작 구간·목표 분량·마지막 구간·구간 내 위치를 저장하고 재접속 시 복원한다.
- 위치 저장 실패 시 확보한 위치를 로컬에 보관하고 재전송한다. 저장 주기·충돌 처리 방식은 미정이다.
- 이는 일시적인 네트워크 단절에 대한 저장 실패 대응이다. 오프라인에서 신규 본문 조회·추천 등 전체 서비스를 제공하는 기능은 확정 범위에 포함하지 않는다. 지연 재전송 요청과 다른 기기·탭의 최신 저장이 충돌할 때의 처리 방식은 미정이다.
- 앞부분을 다시 읽을 때 재개할 현재 위치와 이미 읽은 분량의 계산 기준을 어떻게 구분할지는 미정이다.
- 완료는 선택한 분량을 모두 읽은 경우에만 인정하고 서버에서 검증한다. 책 전체 완독과 구분하며, 같은 세션의 완료 요청이 반복되어도 기록은 한 번만 남긴다.
- 상태안: `reading` → `paused` → `reading`, 목표 도달 후 `completed`. 완료된 기록은 진행 저장으로 다시 열지 않는다.

## 완료 후 행동

- PRD 기준으로 그만 읽기·공유하기·추천하기(대비 추천)를 P0로 제공한다. 기본 공유의 대상·공개 범위·구현 방식은 미정이다.
- 공유 카드는 PRD의 FR-09에 따라 P1이다.
- 같은 책 더 읽기·주간 독서 칸·연속 독서 일수는 현재 PRD의 MVP 필수 범위에 포함하지 않는다.

## 추가 확정 사항

- 개인정보·독서 기록 보관 및 삭제 기간, 운영 도메인에 맞는 쿠키·프록시 설정.
- 동시에 진행할 수 있는 독서 세션 수와 여러 기기에서의 위치 충돌 처리.
