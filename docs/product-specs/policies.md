# 서비스 정책

PRD를 기준으로 한 개발 초안. 별도 표시한 제안·미정 항목은 구현 전에 확정한다.

## 사용자와 인증

- 핵심 기능은 로그인 후 이용하며, 초기에는 구글 로그인만 제공한다.
- 인증 구성안: 구글 OIDC 로그인 → 서버 세션 생성 → 세션 쿠키로 로그인 유지. 서비스용 JWT는 발급하지 않는다.
- 최초 구글 로그인 시 회원 자동 생성은 제안 사항이다. 사용자 식별은 `oauth_provider`와 `oauth_subject` 조합을 사용하며, 구글의 `sub`를 저장한다. 이메일은 식별키로 사용하지 않는다. [구글 공식 문서](https://developers.google.com/identity/openid-connect/openid-connect)
- 로그아웃 시 서버 세션을 무효화하고 세션 쿠키를 제거한다. 다른 사용자의 취향·독서 기록에는 접근할 수 없다.

## 독서 분량과 진행

- 사용자는 PRD에 따라 3·5·10·n장을 선택한다. 1장의 기준과 n의 상한은 미정이다.
- DB는 본문 구간과 `target_segments`로 분량을 관리한다. 장과 구간의 대응은 미정이며, 화면 크기에 따른 페이지 수를 저장 기준으로 사용하지 않는다.
- 도서·시작 구간·목표 분량·마지막 구간·구간 내 위치를 저장하고 재접속 시 복원한다.
- 위치 저장 실패 시 확보한 위치를 로컬에 보관하고 재전송한다. 저장 주기·충돌 처리 방식은 미정이다.
- 완료는 선택한 분량을 모두 읽은 경우에만 인정하고 서버에서 검증한다. 같은 세션의 완료 요청이 반복되어도 기록은 한 번만 남긴다.
- 상태안: `reading` → `paused` → `reading`, 목표 도달 후 `completed`. 완료된 기록은 진행 저장으로 다시 열지 않는다.

## 완료 후 행동

- PRD 기준으로 그만 읽기·공유하기·대비 추천을 제공한다. 공유 대상과 공개 범위는 미정이다.
- 같은 책 더 읽기·주간 독서 칸·연속 독서 일수는 흐름도에만 있어 MVP 포함 여부를 확정해야 한다.

## 추가 확정 사항

- 세션 만료 시간과 서버 세션 저장소, 개인정보·독서 기록 보관 및 삭제 기간.
- 동시에 진행할 수 있는 독서 세션 수와 여러 기기에서의 위치 충돌 처리.
