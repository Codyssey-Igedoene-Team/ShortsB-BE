# 추천 정책

갱신일: 2026-11-01. 제품 흐름은 [PRD](prd.md), 페이지·판본은 [콘텐츠 기준](content.md), 연동은 [FastAPI 인계 문서](../plans/fastapi-ai-handoff.md)를 따른다. 현재 문서는 구현 기준이며 실제 GPU 추론·추천 검증 완료를 의미하지 않는다.

## 입력과 추천 경로

- 요청은 1~10페이지, 필수 카드 하나, 선택 자유 프롬프트다. 카드: 따뜻한 이야기·유쾌한 이야기·생각할 이야기·무엇이든 좋아요.
- 초기 후보는 전달된 15개 작품 자료 중 권한·본문을 확인해 승인한 작품이다. 본문이 짧다는 이유로 제외하지 않는다.
- 검색 대상은 전체 본문 범위의 구간이다. 책 소개·제목 검색만으로 본문 대목 검색을 대체하지 않는다.

| 카드 | 프롬프트 | 처리 |
| --- | --- | --- |
| 따뜻한·유쾌한·생각할 | 없음 | 해당 카드의 사전 query 벡터와 본문 document 벡터 비교 |
| 따뜻한·유쾌한·생각할 | 있음 | 요청 시 프롬프트 query 생성, 카드·프롬프트 각각의 본문 유사도 점수 가중 조합 |
| 무엇이든 좋아요 | 있음 | 프롬프트 query만으로 검색 |
| 무엇이든 좋아요 | 없음 | 유효 작품별 균등 무작위로 책 선택 후 기본 발췌 제공. 모델 호출 없음 |

카드·프롬프트 점수 가중치와 검색 문장은 후속 확정한다. 벡터 합산이 문장 결합 후 임베딩과 같다고 가정하지 않는다. 입력 쪽수는 표시 범위에 적용하며 의미 검색 문장에 섞지 않는다.

## 기본 추천

- 권한 승인·유효 본문이 있는 작품 각각에 동일 선택 확률을 부여한다. 페이지·검색 구간 수가 긴 작품의 선택 확률을 높이지 않는다.
- 책을 먼저 고르고 첫 페이지부터 min(요청 쪽수,전체 쪽수)를 기본 발췌로 제공한다. ANY 단독에는 임의 중간 대목 검색이나 추가 query 임베딩을 수행하지 않는다.
- 같은 작품이 연속으로 나올 수 있다. 사용자별 순환·최근 추천 제외·개인화 가중은 초기 필수 구현이 아니다.
- 요청량보다 짧으면 전체 페이지를 제공한다. 권한·본문 확인은 균등 선택 전에 적용한다.

`shortb_grid.csv`는 키워드 사전이 아니라 주제 5개와 종류 3개를 연결한 15개 작품 표다.

| 공통 주제 | 따뜻한 | 유쾌한 | 생각할 |

| 사랑·그리움 | 메밀꽃 필 무렵 | 동백꽃 | 기다리다 |
| 가난·돈 | 크리스마스 선물 | 봄봄 | 운수 좋은 날 |
| 외로움 | 백야 | B사감과 러브레터 | 지하로부터의 수기 |
| 부끄러움·체면 | 황금풍경 | 벌거벗은 임금님 | 인간 실격 |
| 이기심·책임 | 이기적인 거인 | 치숙 | 프랑켄슈타인 |

`shortb_axes.csv`에는 형식·종류·주제·시선·중심 인물·어조·태도·결말·시대/배경·길이와 대비 후보 3개가 있다. 메타데이터는 검색 문장·설명 검토에 활용하되 임베딩 결과나 정확한 본문 근거 위치로 취급하지 않는다. 카드에 따른 강제 필터·태그 점수 반영의 상세 범위는 후속 계약에서 정한다.

‘결’은 작품 전체의 정서적 질감·성격, 어조는 서술 말투·표현, 결말은 마무리다. CSV의 `(결)`을 `(결말)`로 바꾸지 않는다. 현재 DB의 4종 대비 유형에 축소 매핑하지 않는다. 새 기준은 아래 6개 축이며 코드·스키마 반영은 후속 구현 작업이다.

## 확정된 대비 축과 근거 계약

| 대비 축 | 의미 |
| --- | --- |
| 결 | 작품 전체에서 느껴지는 정서적 질감·성격 |
| 시선 | 이야기를 바라보는 관점·서술 시점 |
| 어조 | 서술 말투·표현 방식 |
| 태도 | 인물/작품이 상황을 대하는 방식 |
| 결말 | 마무리 방식 |
| 시대·배경 | 시간·공간·사회적 배경 |

- axes CSV는 작품 15개의 방향 있는 후보 항목 45개다. 이를 전부 승인된 관계로 취급하지 않는다. 중복·역방향은 ID와 축을 기준으로 확인한다.
- 대비 1·2·3은 후보 목록이다. 숫자를 점수나 우선순위로 사용하지 않는다.
- 관계는 기준 작품·대상 작품·대비 축 단위로 구분한다. 같은 작품 쌍도 축이 다르면 별도 관계며 역방향은 별도 검수한다.
- 관계마다 공통 연결점, 양쪽 정확한 원본 근거 위치, 추천 이유, 검수 상태를 관리한다. 근거는 페이지 또는 페이지 범위와 필요 시 페이지 내 위치를 연결한다.
- 상태는 검토 중(pending)·승인(approved)·제외(rejected)다. 후보와 승인 관계를 분리한다는 것은 상태/조건의 구분이며 별도 후보 테이블 도입을 필수로 요구하지 않는다.
- pending 자료에 근거가 없으면 미완료 상태를 그대로 유지한다. 빈 값·임의 문장으로 근거를 채워 승인하지 않는다. approved는 실제 양쪽 근거·설명·권한 검토를 통과해야 한다.
- 첫 발췌 범위에 기준 근거가, 두 번째 발췌 범위에 대상 근거가 포함돼야 한다. 필요한 근거 범위가 2쪽인데 요청이 1쪽이라면 범위를 충족하지 못하는 관계를 사용하지 않는다.
- 임베딩 검색은 근거 후보 대목을 찾는 보조 수단이며 검수 승인을 대체하지 않는다. 근거 데이터는 시연에 사용할 관계부터 준비할 수 있다.
- 에이전트는 본문을 직접 읽지 않는다. 사람이 검수한 위치·설명을 전달받고, 프로그램은 양쪽 원본 ID·유효 범위·포함 관계를 본문 출력 없이 확인한다.
- 실제 근거 위치와 설명 승인 자료는 아직 미완료다. 이번 결정과 문서 갱신을 데이터 검수·DB 변경 완료로 보고하지 않는다.

## 사전 임베딩과 FastAPI

- Python 스크립트: 전체 본문의 각 검색 구간을 document로, 고정 카드 3종의 검색 문장을 query로 사전 생성.
- FastAPI: GPU 모델을 로딩·재사용하고 프롬프트가 있는 요청을 query로 임베딩. ANY 벡터는 생성하지 않음.
- Spring: DB 저장·조회, 유사도·점수 조합, 기본·대비 정책, 실제 페이지 범위·본문 응답.
- 사전/온라인은 같은 모델·revision·차원·정규화·전처리/템플릿 버전을 사용하며 query/document 입력 지침을 지킨다. 불일치 벡터는 섞지 않는다.
- 모델·GPU 연결·가중치·벡터 저장 방식은 지금 확정하지 않는다. 제공 GPU의 실제 실행 확인은 필수이며 직접 학습·파인튜닝은 요구하지 않는다.

## 발췌 범위

- pages 하나를 서비스 페이지 하나로 사용한다. 길면 그 안의 검색 구간만 세분화하고 원본 페이지와 위치를 유지한다.
- 작품 전체가 P쪽, 요청이 N쪽이면 실제 수 A=min(N,P). P=0 등 잘못된 자료는 제외한다.
- 검색된 페이지를 포함하는 연속 A쪽을 선택한다. 끝부분에서는 시작을 앞쪽으로 조정한다. 정확한 가운데 배치 등 동률 규칙은 구현 계약에서 고정한다.
- 서로 떨어진 결과를 이어 붙이지 않는다. 요청량·실제량·전체량·시작/끝 페이지를 구분한다.
- 대비 작품도 원래 N으로 독립 계산한다. 첫 작품이 짧아서 8쪽을 보여줬어도 원래 요청이 10쪽이면 다음 20쪽 작품에서는 10쪽을 제공한다.

## 대비 추천

1. 첫 발췌의 작품·실제 페이지/근거 범위를 확인한다. 전체 독서 세션 완료를 선행 조건으로 요구하지 않는다.
2. CSV의 대비 후보와 검수 자료에서 첫 발췌 안의 근거로 설명할 수 있는 관계를 찾는다.
3. 다른 작품의 권한·본문·근거 위치·설명 일치를 확인한다. CSV에 후보가 있는 것만으로 승인하지 않는다.
4. 승인 관계 후보 안에서 관련 본문 벡터를 검색·정렬한다. 분위기 대비인데 첫 카드 성향을 무조건 다시 강제해 대비를 제거하지 않도록 별도 검토한다.
5. 두 번째 근거를 포함하는 연속 min(N,두 번째 전체 쪽수) 발췌와 공통 주제·대비 축·이유를 제공한다.

책 ID만 일치한다고 첫 발췌 밖의 근거를 사용하지 않는다. 양쪽 본문 벡터는 재사용하며 매 대비 요청에 전체 책을 재임베딩하지 않는다. 낮은 유사도 자체는 반대 관점의 근거가 아니다. 자료가 비대칭이면 반대 방향 관계를 자동 승인하지 않는다.

현재 스키마에는 source_segment_no·target_segment_no와 복합 FK가 있다. 다만 CSV에는 정확한 양쪽 근거 위치가 없어 추가 연결·검수가 필요하다. 저장된 구간 참조 자체로 설명 일치나 발췌 포함 검증이 끝난 것은 아니다.

첫 발췌에 근거가 없거나 유효 관계가 없으면 대비를 생략하고 첫 작품의 전체 독서는 시작할 수 있게 한다. API에서는 대비 후보 없음으로 응답한다. 모델 장애와 관계 없음은 구분한다. 오류 세부 응답은 API 초안에서 확정한다. 관계 부족을 임의의 책·설명 생성으로 채우지 않는다.

## 전체 독서·보류 범위

- 두 발췌 중 고른 작품의 첫 페이지에서 전체 독서 세션을 시작한다. 발췌 결과의 시작 페이지를 신규 전체 독서 시작점으로 쓰지 않는다.
- 전체 독서 시작부터 전체 책 기준 진행률·위치·완료를 관리한다. 발췌 완료와 전체 완독을 혼용하지 않는다.
- 기본 공유·공유 카드 모두 무기한 보류다.
- 성과 측정·이벤트 확장 보류를 유지하며 recommendation_logs를 최초 추천·발췌 기록 구조로 즉시 변경하지 않는다.
- 최근 추천 제외·이용 기록 기반 개인화·시간 입력과 분량 환산은 필수 범위가 아니다.
