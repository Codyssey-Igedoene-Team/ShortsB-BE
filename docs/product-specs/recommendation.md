# 추천 정책

PRD 기준의 핵심 규칙과 구현 제안. AI 모델 선택은 보류한다.

## 최초 추천

- 이용 권한과 본문이 확인된 도서 중 선택 분량을 제공할 수 있는 후보를 추천한다.
- 저장된 장르·관심 주제·분위기 취향을 활용하고 도서 정보·추천 이유를 함께 제공한다.
- 취향 입력을 건너뛸 때 검토된 기본 후보를 제공하는 방식을 제안한다. 건너뛰기 허용 여부는 미정이다.

### 현재 콘텐츠 속성의 한계

- `user_preferences`는 `favorite_genres`·`interests`·`preferred_moods`를 저장하지만, 현재 `books`에는 장르를 위한 `genre` 외에 관심 주제·분위기를 매칭할 전용 속성이 없다. `book_segments`에도 주제·분위기 속성이 없다.
- `book_relations.common_topic`은 특정 대비 관계의 공통 주제다. 모든 도서·구간의 최초 추천용 주제 속성을 대체하는 것으로 확정하지 않는다.
- 따라서 현재 스키마만으로 세 가지 취향을 일관되게 매칭하는 규칙이 정해진 것은 아니다. 도서 또는 구간 중 어떤 단위에 주제·분위기를 부여할지, 허용 값과 저장 방식 및 매칭 규칙을 정해야 한다.
- 메타데이터 추가 방식과 스키마 변경은 미정이다. 자유 서술형 소개문을 이용한 자동 매칭도 확정된 구현이 아니다.

## 대비 추천

- 읽은 책과 공통 주제가 있으면서 관점·주장·분위기·작가 생애가 대비되는 관계를 사용한다.
- 관계마다 공통 주제, 양쪽 본문 근거, 추천 이유를 저장한다. 의미 유사도가 낮다는 이유만으로 대비라고 판단하지 않는다.
- AI 사전 분석 → 사람 검수 → DB 저장 순서로 준비한다. 요청마다 전체 본문을 분석하지 않는다.
- `review_status` 값은 `pending`·`approved`·`rejected`를 제안하며, 승인된 관계만 노출한다.
- 충분한 근거가 없거나 후보가 없으면 대비 추천을 생략한다. API는 빈 목록을 반환한다.

### 책 단위 관계와 읽은 구간의 차이

- 현재 `book_relations`는 `source_book_id`와 `target_book_id`로 책을 연결한다. `source_evidence`·`target_evidence`는 텍스트이며, 근거가 위치한 본문 구간이나 구간 내 범위와 구조적으로 연결돼 있지 않다.
- 사용자는 책 전체가 아닌 선택한 분량을 읽으므로, 승인된 책 단위 관계라도 사용자가 읽지 않은 부분을 근거로 추천할 수 있다. 현재 구조만으로는 해당 근거가 완료한 독서 범위에 포함되는지 검증하기 어렵다.
- 읽은 내용과 연결된 추천을 보장하려면 양쪽 근거의 구간·범위 연결과 읽은 범위에 대한 검증 방식을 정해야 한다. 구체적인 필드·관계 구조는 미정이며, 책 단위 관계 승인을 구간 검증 완료로 간주하지 않는다.

### 다음 읽기로의 연결

- 대비 추천을 선택한 뒤 책의 처음부터 읽을지, 대비 근거가 있는 구간부터 읽을지 미정이다.
- 이전 선택 분량을 유지할지, 1~10장 중 다시 선택할지 미정이다.
- 현재 대비 추천 응답에는 다음 세션 생성에 필요한 시작 구간·목표 분량이 없다. 해당 값을 추천 응답에 포함할지, 선택 후 서버에서 결정할지 확정해야 한다. `api.md`의 미결정 계약을 참고한다.

## 기록과 미정 사항

- 기존 초안은 대비 추천 노출·클릭·읽기 시작 기록을 `recommendation_logs`에 남기며, 이벤트 값으로 `shown`·`clicked`·`started`를 제안한다.
- 이 테이블은 대비 관계 기반 기록이며, 최초 추천 기록까지 포함하는 구조는 아니다.
- 성과 측정 범위와 이벤트 수집 계약의 확정·확장은 보류한다. 현재 분석에서 로그 테이블이나 이벤트 API 변경을 확정하지 않는다.
- MVP 우선 대비 유형, 추천 개수·정렬·재노출 기준, 검수 담당자는 미정이다.
- 이용 기록에 따른 추천 순위 개선은 PRD의 P1 범위다.
