# ShortSB

제품 요구사항 정의서 | 버전 0.4 · 2026-11-01 · 최신 협의 반영

**한 줄 정의:** 원하는 쪽수와 이야기 성향을 선택하면 두 작품의 맞춤 발췌와 대비를 경험하고, 마음에 드는 작품의 전체 독서로 이어지는 서비스.

이 문서는 현재 제품 요구의 기준이다. API 경로·필드의 미합의 사항은 `api.md`의 초안 표시를 따른다. 문서 갱신은 코드·DB 구현 완료를 의미하지 않는다. R1 인증은 사용자 검증 완료다. R2 첫 추천·도서와 R3 전체 독서 코드를 작성했으나 실제 DB/GPU·API 실행은 미검증이다. R4 대비도 코드·검토 양식을 작성했으며 실제 근거 승인·DB/API 검증은 대기 중이다.

## 1. 제품 개요와 목표

- 짧은 발췌로 읽을 작품을 탐색하고, 공통 연결점과 다른 정서·시선을 비교한다.
- 첫 발췌와 대비 발췌 중 원하는 작품을 선택해 전체 본문을 첫 페이지부터 읽는다.
- 전체 독서에서는 위치 저장·이어 읽기·전체 책 기준 진행량을 제공한다.
- 모바일 중심 웹과 React 프런트에 Spring 업무 서버·FastAPI 임베딩 서버를 연결한다.
- 핵심 기능은 Google 소셜 로그인 후 이용한다. 서버 세션·쿠키를 사용하며 서비스용 JWT는 발급하지 않는다.

## 2. 사용자 입력과 시나리오

| 입력 | 필수 여부 | 기준 |
| --- | --- | --- |
| 발췌 쪽수 | 필수 | 1~10의 정수 |
| 이야기 카드 | 필수·하나 선택 | 따뜻한 이야기 / 유쾌한 이야기 / 생각할 이야기 / 무엇이든 좋아요 |
| 자유 프롬프트 | 선택 | 원하는 내용·상황. 최대 길이는 구현 계약에서 결정 |

구글 로그인 → 쪽수 선택 → 카드 선택 → 자유 프롬프트 선택 입력 → 첫 작품의 맞춤 발췌 → 대비 작품의 발췌 → 두 작품 중 전체 독서할 책 선택 → 첫 페이지부터 전체 독서 → 중단·재개·전체 책 완료.

‘무엇이든 좋아요’도 유효한 필수 카드 선택이다. 카드 선택 자체를 건너뛰는 흐름은 두지 않는다. 과거의 장르·관심 주제·분위기 배열 입력은 현재 필수 사용자 흐름에서 사용하지 않는다. 재방문 시 기존 전체 독서 세션은 저장 위치에서 이어 읽는다.

## 3. 페이지·검색 구간·발췌

- 제공 자료 `books.json`의 `pages` 항목 하나를 서비스 1페이지로 사용한다. 종이책 쪽수·화면 크기·원문 챕터와 구분한다.
- 자료 배열과 chapters 범위는 0부터 시작하며 화면·업무 API 페이지 번호는 1부터 사용한다. chapters의 `[start, end)` 변환은 가져오기 단계에서 명시한다.
- 페이지를 검색 구간의 기본으로 삼고, 모델 입력 길이를 넘는 페이지는 문맥을 보존해 내부 분할한다. 검색 구간마다 원본 페이지·필요한 위치를 연결한다. 원래 표시 페이지를 다시 나누지 않는다.
- 검색된 대목을 포함하는 연속 페이지를 제공한다. 흩어진 여러 대목을 연속 페이지처럼 섞지 않는다.
- 실제 발췌 수는 `min(요청 쪽수, 작품 전체 페이지 수)`다. 짧은 작품을 요청량 부족만으로 제외하지 않는다. 빈 본문·잘못된 자료·미승인 콘텐츠는 제외한다.
- 끝부분에서는 시작점을 앞으로 조정해 검색 근거를 포함한 최대 분량을 확보한다.
- 첫 작품과 대비 작품에 같은 요청 쪽수를 적용하지만 실제 제공 수는 작품마다 다를 수 있다. 요청 10쪽·첫 책 전체 8쪽·대비 책 전체 20쪽이면 각각 8쪽과 10쪽을 제공한다.

## 5. 추천과 임베딩

- 사전에 마련한 15개 작품 자료를 초기 콘텐츠 기준으로 사용한다. 권한·판본 확인 후 승인한 데이터만 공개한다.
- 전체 본문 범위의 각 구간을 사전 임베딩한다. 책 전체를 하나의 벡터로 만들거나 소개만 임베딩해 대목 검색을 대체하지 않는다.
- 고정 카드 중 따뜻한·유쾌한·생각할 이야기의 검색 문장은 사전 임베딩한다. ANY는 분위기 제한 없음이며 벡터를 만들지 않는다.
- 프롬프트가 있을 때만 요청 시 query 임베딩을 수행한다. 카드·프롬프트 각각의 본문 코사인 유사도를 기본 40%·60%로 조합한다. 프롬프트 비중은 0~1 설정으로 조정하고 카드 비중은 나머지다.
- ANY 단독은 유효 작품 중 각 작품을 같은 확률로 선택한다. 긴 작품의 구간 수 때문에 선택 확률이 커지지 않게 책을 먼저 선택한다. 선택된 작품의 첫 페이지부터 min(요청 쪽수,전체 쪽수)를 제공한다.
- 모델은 제공 GPU에서 공개 한국어 모델을 직접 실행한다. 사전 처리 Python과 요청 처리 FastAPI가 같은 encoder를 사용하고 Spring이 추천 정책·DB·페이지를 담당한다.
- 직접 학습·파인튜닝·실시간 외부 전체 도서 수집·자동 번역·생성형 설명 모델은 필수 범위가 아니다. 자료에 포함된 사전 AI 번역판 사용과 서비스의 자동 번역 기능은 구분한다.
- 모델은 KURE-v1의 GPU 기본 추론을 확인했다. 벡터 저장은 PostgreSQL double precision[]·초기 Spring 유사도 계산으로 확정했다. 등록 SQL·수동 가져오기를 작성했으나 DB 적용·실제 도서 벡터 생성은 대기 중이다. 고정 revision·실제 서버 통합은 추가 확인한다. 첫 추천/발췌 재조회/도서 정보 API 코드를 작성했으며 실행 검증은 대기 중이다.

## 6. 대비 자료와 검수

- `shortb_grid.csv`는 사랑·그리움, 가난·돈, 외로움, 부끄러움·체면, 이기심·책임의 5개 주제를 3종 이야기 작품에 연결한다.
- `shortb_axes.csv`는 작품 속성 10개 축과 작품별 대비 후보 3개를 제공한다. 모든 조합을 자동 승인하거나 대칭 관계로 간주하지 않는다.
- ‘결’은 작품 전체의 정서적 질감·성격이다. 어조는 서술 말투·표현, 결말은 마무리 방식으로 구분한다.
- 전달된 자료는 작품 수준 후보·속성 기준이다. 양쪽 정확한 근거 위치·설명 검수는 별도로 필요하다.
- 첫 발췌에 실제 포함된 근거와 연결되는 관계를 사용하고, 두 번째 발췌도 해당 근거를 포함한다. 책 ID만 일치한다고 발췌 밖 근거를 사용하지 않는다.
- 유사도가 낮다는 이유만으로 반대 관점을 주장하지 않는다. 전역 결말·작가 정보가 대비 근거라면 실제 발췌로 그 설명을 뒷받침하는지 별도 확인한다.
- 대비 축은 CSV에서 실제 사용하는 결·시선·어조·태도·결말·시대·배경 6개를 그대로 사용한다. 기존 DB의 4종에 축소 매핑하지 않고 별도 book_contrast_relations·003 변경 SQL·등록/API 코드를 작성했다. 실제 SQL 적용·검수 승인은 대기 중이다. 기준 작품·대상 작품·축별로 관계를 구분하고 후보/승인/제외 상태를 관리한다.

## 7. 콘텐츠·품질·검증 기준

- 자료 README 기준 한국어 원문 6편·AI 한국어 전문 번역 9편이다. AI 번역은 전문 번역가 교열 전이며 중역 등 판본 안내를 유지한다. 원문·번역·추천 설명을 구분한다.
- README의 전문 표시는 제공자 설명이다. 본문을 에이전트가 읽어 완전성을 검증한 것으로 취급하지 않는다.
- 본문 출력 없이 pageCount·pages 개수·재결합 text·SHA-256·chapter 범위를 프로그램으로 검증한다. 이 검증만으로 원작 대비 누락 부재를 보장하지 않는다.
- 무단 사용자 데이터 접근, CSRF 없는 상태 변경, 미승인 콘텐츠 노출을 차단한다.
- 임베딩 후보 없음·모델 장애·근거 부족을 구분한다. 오류를 임의 본문·관계 생성으로 숨기지 않는다.
- 네트워크 단절 중 확보한 전체 독서 위치의 보관·재전송은 프런트와 합의한다. 전체 오프라인 서비스는 필수 범위가 아니다.
- 성과 측정과 이벤트 수집 계약 확장은 보류한다. 서비스 지표 후보는 추천 후 전체 독서 시작·이어 읽기 성공·근거 일치이며 수치 목표는 미정이다.

## 9. 후속 확정: 발췌 보관·재개·저장 충돌

- ANY 단독은 균등 무작위로 고른 책의 첫 페이지부터 제공한다. 카드·프롬프트가 있는 요청은 임베딩 검색 대목을 사용한다.
- 첫 발췌에 대비 근거가 없거나 유효 후보가 없으면 대비만 생략하고 첫 책 전체 독서 시작을 제공한다.
- 발췌 식별자·원래 입력·작품/실제 범위는 세션에 임시 보관한다. 본문은 DB에서 조회한다. 세션 소실 시 새 추천을 요청하며 전체 독서 기록은 DB에 유지한다.
- 회원·책별 미완료 전체 독서 세션은 하나다. 다시 선택하면 기존 현재 위치로 재개하고 완료한 책이면 새 세션의 첫 페이지부터 시작한다. 다른 책의 미완료 세션은 함께 유지할 수 있다.
- 현재 위치는 재개에, 최대 도달 위치는 진행률에 사용한다. 앞부분으로 돌아가도 최대 위치/진행률은 감소하지 않는다. 모든 앞 페이지를 읽었다는 증명과는 구분한다.
- 진행 저장·중단·완료는 조회 버전을 보내고 서버의 현재 버전과 같을 때만 원자적으로 갱신·버전 증가한다. 과거 버전은 409와 최신 현재/최대 위치·상태·버전을 반환하고 요청을 반영하지 않는다.
- 프런트는 충돌 안내·최신 상태를 반영하되 과거 요청의 버전만 바꿔 자동 재전송하지 않는다. 거절된 과거 요청으로 최대 위치도 갱신하지 않는다. 진행률은 페이지 구분자를 제외한 본문 UTF-16 길이 대비 최대 누적 위치로 계산해 소수 둘째 자리까지 내림한다. 페이지 이동·중단·완료 직전 저장을 사용하며 스크롤 저장 간격은 프런트 통합에서 정한다. 발췌 보관은 세션당 10개·초과 시 가장 오래된 생성 항목 제거로 구현했다.
