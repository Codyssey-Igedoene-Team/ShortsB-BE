# ShortSB

제품 요구사항 정의서 | Product Requirements Document

버전 0.2 · 2026-10-31 · 해커톤 MVP 초안 · 팀 검토용

**한 줄 정의:** 사용자가 원하는 읽기 분량을 선택하면 취향에 맞는 책의 실제 본문을 추천하고, 선택한 분량을 완료하면 서로 대비되는 책으로 호기심을 이어주는 독서 서비스.

**문서 원칙:** 확정된 요구사항과 제안·미결정 사항을 구분한다. 수치 및 기술 선택은 별도 확정 전까지 목표 또는 예시로 취급한다.

## 1. 제품 개요

| 구분 | 내용 |
| --- | --- |
| 제품명 | ShortSB (가칭) |
| 핵심 경험 | 분량 선택 → 개인화 책/본문 추천 → 읽기·중단·재개 → 완료 → 공유·대비 추천 |
| 핵심 가치 | 짧게 시작할 수 있는 독서, 읽던 자리 복귀, 비교와 반전이 만드는 다음 독서 동기 |
| 제공 형태 | 모바일 중심 반응형 웹(제안) |
| 인증 | 구글 소셜 로그인 후 서버 세션 생성, 세션 쿠키로 로그인 유지 |

## 2. 문제 정의

- 사용자는 책을 읽기 전에 무엇을 읽을지, 얼마나 읽을지 결정해야 하는 부담을 느낄 수 있다.
- 짧은 독서 도중 이탈하면 다시 읽던 위치로 돌아오는 과정이 번거롭다.
- 한 번의 독서가 끝난 뒤 다음 책을 발견할 흥미로운 연결고리가 부족하다.

위 내용은 검증이 필요한 제품 가설이며, 실제 사용자 인터뷰와 사용성 테스트를 통해 확인한다.

## 3. 목표 및 성공 지표

| 제품 목표 | 측정 지표 | 초기 검증 방식 |
| --- | --- | --- |
| 빠른 독서 시작 | 첫 추천에서 읽기 시작한 비율 | 신규 사용자 시나리오 테스트 |
| 중단 후 자연스러운 복귀 | 중단 세션 재개 성공률 | 새로고침·재접속 테스트 |
| 완료 후 다음 독서 유도 | 대비 추천 클릭/읽기 시작률 | 추천 유형별 이벤트 측정 |
| 추천 신뢰성 | 추천 이유의 근거 일치율 | 콘텐츠·작가 정보 수동 검토 |

구체적인 목표 수치는 표본 규모와 시연 환경을 고려하여 팀이 확정한다. 성과 측정 범위와 이벤트 수집 계약의 확정·확장은 보류한다.

## 4. 타깃 사용자

**1차 타깃:** 독서에 관심은 있지만 긴 분량을 시작하기 부담스럽거나, 짧은 여유 시간에 읽을 콘텐츠를 찾는 사용자.

**대표 페르소나(가설):** 통학 중 앱을 연 사용자가 5장을 선택하고, 취향에 맞는 글을 읽다가 목적지에 도착해 중단한다. 다음 접속에서 같은 위치부터 이어 읽고, 완료 후 상반된 관점의 책을 탐색한다.

## 5. 경쟁 서비스 분석

**비교 대상(검토 예정):** 전자책 구독 서비스, 도서 요약 서비스, 개인화 도서 추천 서비스. 서비스별 실제 기능·요금·콘텐츠 정책은 조사 후 기입한다.

| 비교 기준 | ShortSB의 검증할 차별화 |
| --- | --- |
| 독서 진입 | 사용자가 먼저 1~10장 중 원하는 정수 분량을 자유롭게 선택 |
| 이탈 대응 | 구간·위치 기반 중단 및 재개 |
| 다음 콘텐츠 | 유사성뿐 아니라 관점·분위기·주장·작가 생애의 대비 관계 추천 |

## 6. 사용자 시나리오

구글 소셜 로그인 → (취향 입력 또는 기존 취향 불러오기, 취향 입력 건너뛰기 허용 여부는 미정) → 1~10장 중 원하는 정수 분량 선택 → 추천 도서·구간 확인 → 읽기 시작 → [중단: 위치 저장 후 종료 / 완료: 완료 화면] → 그만 읽기·공유하기·추천하기 → 대비 추천 선택 시 다음 책 읽기.

**재방문:** 진행 중인 세션이 있으면 ‘이어 읽기’를 우선 제공하고, 새 추천을 받을 수도 있게 한다.

## 7. 기능 요구사항

P0 = 핵심 MVP, P1 = 확장 또는 일정에 따른 선택 기능. 완료 조건은 테스트 가능한 형태로 기술한다.

| ID | 우선 | 기능 | 요구사항 및 수용 기준 |
| --- | --- | --- | --- |
| FR-01 | P0 | 분량 선택 | 독서 시작 전 1~10장 중 원하는 정수 분량을 자유롭게 선택한다. 선택값은 추천 요청에 반영된다. 1장의 정의와 내부 본문 구간의 대응은 미정이다. |
| FR-02 | P0 | 취향 기반 추천 | 최초 구현부터 콘텐츠 사전 임베딩과 사용자 관심사 유사도 검색을 사용한다. 명시적 취향 및 선택 분량에 맞는 검토된 도서/본문 구간을 추천하고 추천 이유와 책 정보를 표시한다. |
| FR-03 | P0 | 본문 읽기 | 추천한 실제 본문을 제공하고, 현재 읽기 진행률과 선택 분량 대비 남은 양을 보여준다. |
| FR-04 | P0 | 진행 기록 저장 | 읽기 중 나가거나 새로고침해도 도서·구간·마지막 위치·선택 분량을 저장하고 복원한다. |
| FR-05 | P0 | 완료 판정 | 선택한 분량을 모두 읽으면 완료 상태로 전환한다. 중복 완료 기록을 방지한다. |
| FR-06 | P0 | 완료 화면 | 완료 시 ‘그만 읽기’, ‘공유하기’, ‘추천하기’ 세 가지 행동을 제시한다. |
| FR-07 | P0 | 대비 도서 추천 | 현재 읽은 내용과 공통 연결점이 있으면서 관점·주장·분위기·작가 생애가 대비되는 후보를 보여준다. |
| FR-08 | P0 | 추천 근거 | 왜 대비되는지 유형과 근거를 짧게 설명한다. 근거 없는 관계는 표시하지 않는다. |
| FR-09 | P1 | 공유 카드 | 책 제목, 읽은 구간 소개, 서비스 링크를 공유한다. 원문 인용은 이용 권한을 확인한 범위만 허용한다. |
| FR-10 | P1 | 추천 개인화 개선 | 사용자의 선택·완료·추천 클릭 기록을 다음 추천 순위에 반영한다. |

### 7.1 대비 추천 유형 및 동작

| 추천 유형 | 선정 원칙 | 사용자에게 보여줄 설명 예시 |
| --- | --- | --- |
| 관점 대비 | 동일 주제·질문에 대해 다른 해석을 가진 본문 | “같은 문제를 다른 눈으로 보면?” |
| 주장 대비 | 비교 가능한 쟁점에 대해 상반된 주장을 가진 본문 | “이 주장에 반대하는 작가는?” |
| 분위기 대비 | 주제 연관성을 유지하면서 정서·문체가 다른 본문 | “같은 고민, 전혀 다른 분위기” |
| 작가 생애 대비 | 검증된 생애 사건·환경이 뚜렷이 다른 작가의 작품 | “서로 다른 삶에서 나온 이야기” |

**주의:** 단순히 의미 유사도가 낮다는 이유로 ‘반대’라고 분류하지 않는다. 작가의 생애를 행복/불행 이분법으로 단정하지 않으며, 검증된 사실과 출처를 사용한다.

### 7.2 추천 데이터 처리 흐름

콘텐츠 확보 및 이용 권한 확인 → 본문 구간 분할 → AI로 주제·관점·분위기·작가 정보 후보 분석 → 관계 후보 생성 → 사람 검토 → DB 저장 → 사용자 분량·취향 조건으로 후보 필터링 → 대비 유형별 추천 및 이유 표시.

MVP는 사전 분석·저장 방식을 기본으로 한다. 매 추천 요청마다 전체 책을 새로 분석하거나 모델을 직접 학습할 필요는 없다.

**확정한 최초 추천 구현 방향:** 멘토 제안을 바탕으로 최초 추천 개발부터 제공받은 GPU에서 사전학습된 공개 한국어 임베딩 모델을 직접 실행한다. 모델 학습·파인튜닝 없이 책 소개 또는 검토한 본문 구간을 사전 임베딩하고, 사용자 관심사와의 유사도로 후보를 찾는다. 선택 분량·권한·본문 존재 조건을 함께 적용한다. 임베딩을 후속 단계에서 추가하는 방식으로 진행하지 않으며, 구체적인 모델·저장·연동 방식은 상세계획에서 결정한다.

기존 1~10장 선택은 유지하며, 가용 시간의 입력·추정과 분량 환산 방식은 미정이다. 기록 기반 순위 개선은 FR-10의 P1 범위를 유지한다. 대비 추천은 임베딩 유사도만으로 판정하지 않고 검수된 관계·근거를 사용한다. 상세 검토 항목은 `recommendation.md`와 `../planning-review.md`의 12번을 참고한다.

현재 스키마의 책 단위 대비 관계와 최초 추천용 콘텐츠 속성에는 보완이 필요하다. 읽은 구간과 추천 근거의 연결, 주제·분위기 속성, 대비 추천 이후의 시작 구간·분량 계약은 `recommendation.md`와 `../planning-review.md`의 미결정 사항을 참고한다.

### 7.3 인증 및 완료 후 행동 기준

- 핵심 기능은 구글 소셜 로그인 후 이용한다. 서버 세션을 생성하고 세션 쿠키로 로그인을 유지하며, 서비스용 JWT는 발급하지 않는다.
- 최초 구글 로그인 시 회원을 자동 생성하고 검증된 이메일을 필수 수집한다. MVP는 서버 메모리 세션을 사용하며 비활성 만료 기본값은 30분이다. 서버 재시작 시 재로그인이 필요하다. 개인정보 보관·삭제 기간과 운영 배포 설정은 별도 확정한다.
- 완료는 선택한 분량의 완료를 뜻하며, 책 전체 완독과 구분한다.
- 완료 화면의 그만 읽기·공유하기·추천하기는 P0다. 공유 카드 기능은 FR-09에 따라 P1이며, 기본 공유의 대상·공개 범위·구현 방식은 미정이다.
- 같은 책 더 읽기·주간 독서 칸·연속 독서 일수는 현재 PRD의 MVP 필수 범위에 포함하지 않는다.

| 성능 | 추천 응답 목표를 정하고 지연 시 검증된 대체 후보를 제공한다. |
| 접근성 | 모바일 화면 대응, 충분한 글자 크기, 명확한 버튼 레이블을 제공한다. |

| 콘텐츠 신뢰성 | 실제 원문·판본·번역 출처를 표시하고 AI 생성 설명과 원문을 구분한다. |

## 9. MVP 범위

**반드시 포함(P0):** 구글 소셜 로그인·서버 세션 인증, 1~10장 분량 선택, 취향 기반 추천, 실제 본문 읽기, 중단·재개, 선택 분량 완료, 완료 후 3개 행동, 근거 있는 대비 추천(최소 1개 유형 이상 시연).

**범위 조정 가능:** 대비 추천 네 유형 전체를 한 번에 고도화하는 작업, 공유 카드 기능·꾸미기, 추천 개인화 학습, 추가 소셜 계정 연동, 커뮤니티, 영상 생성, 게임화.

**우선순위 원칙:** 핵심 사용자 흐름을 완성한 뒤 대비 추천 유형을 단계적으로 확장한다. 네 유형은 제품의 목표 기능이며, 해커톤 시연 시 구현 범위를 별도 명시한다.

## 10. 제약사항 및 리스크

| 리스크 | 대응 |
| --- | --- |
| 저작권·번역권 | 원작과 한국어 번역문·판본의 권리를 각각 확인한다. |
| 장 단위의 모호성 | 종이책 페이지/화면/본문 구간 중 하나로 정의하고 진행률 기준을 고정한다. |
| 근거 없는 대비 추천 | 관계별 양쪽 본문 근거와 검토 상태를 저장하고 불확실하면 미노출한다. |
| 작가 생애 정보 왜곡 | 출처가 있는 사건 중심으로 비교하며 ‘불행한 작가’ 같은 단정적 낙인을 피한다. |
| 후보 부족 | 충분한 후보가 없을 때 추천 범위를 설명하거나 대비 추천을 생략한다. |
| 진행률 오류 | 텍스트 위치를 기준으로 저장해 기기 폭·글자 크기 변경에 대응한다. |

| M5 통합 검증 | 공유 동작·모바일 QA·발표 시나리오 | 주요 예외 상황 검증 |

구체적인 날짜와 담당자는 팀 일정 확정 후 추가한다.

## 12. 미결정 사항

- “장”의 정확한 의미: 앱 내 읽기 카드, 고정 글자 수, 종이책 페이지, 원문 구간 중 무엇인가?
- 선택한 1~10장에 해당하는 본문이 부족할 때의 안내와 대체 추천 방식은?
- 첫 방문 시 취향 입력 항목과 건너뛰기 허용 여부는?
- 진행 기록의 기기 간 동기화 범위와 여러 기기·탭의 위치 충돌 처리 방식은?
- 공유하기의 대상: 추천 카드, 완독 기록, 발췌문 중 무엇인가?
- 대비 추천 4종 중 해커톤에서 우선 구현할 유형과 데이터 검수 책임자는?
- 사용할 작품·번역본, 공개 임베딩 모델·외부 AI API, 제공 GPU의 활용 범위, DB, 호스팅, 비용 한도는?

**승인 기준:** 위 미결정 사항 중 읽기 단위·진행 위치·공유 범위·추천 검증 기준은 개발 착수 전에 우선 확정한다.
